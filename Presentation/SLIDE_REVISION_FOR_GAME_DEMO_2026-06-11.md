# 게임 시연 포함 버전 슬라이드 수정 지시

작성일: 2026-06-11

대상: `slide.pdf` 19장 버전

목표: 10분 발표 안에 실제 게임 시연을 넣기 위해 슬라이드 수와 메시지를 압축한다.

---

## 핵심 판단

현재 슬라이드는 논리 흐름이 좋아졌지만, 게임 시연까지 넣으면 19장을 전부 말할 수 없다. 발표 본편은 13-15장 정도로 줄이고, Q&A와 기술 검수는 부록으로 분리한다.

발표의 중심은 다음 세 문장이다.

1. 기존 돌봄지원 심사소는 실행 가능한 수준까지 만들었지만, 사용자가 불명확했다.
2. 그래서 가족치료를 배우는 학생이라는 명확한 이용자로 재정의했다.
3. FT001 한 사례를 깊게 완성해, 개입 선택-가족 반응-슈퍼비전-로그 분석이 한 사이클로 돌아가게 만들고 있다.

---

## 권장 슬라이드 순서

### 1. 제목

현재 1장 유지.

발표 첫 문장에 "가족치료를 배우는 학생을 위한 상담 개입 시뮬레이션"을 명확히 말한다.

### 2. 처음 기획: 돌봄지원 심사소

현재 2장 유지.

단, "구현 현황 실행 가능한 수준까지 구현 완료"는 강조해도 좋다. 기존 프로젝트가 단순 아이디어가 아니라 실제로 만든 결과물이었다는 증거다.

### 3. 문제: 플레이어가 불명확

현재 3장 유지.

이 장은 발표의 전환 이유이므로 반드시 포함한다.

### 4. 사용자 재정의

현재 4장 유지.

이 장은 매우 좋다. 교수님 피드백과 직접 연결된다.

### 5. 가족치료와 비주얼노벨 구조의 접점

현재 5장 유지.

단, 화면 하단 텍스트가 어두운 이미지 위에 있어 다소 약하게 보이면 대비를 올린다.

### 6. 새 프로젝트 구조

현재 6장 유지.

여기서 게임 루프를 더 명확히 표현하면 좋다.

추천 문구:

`대화 관찰 -> 개입 선택 -> 가족 반응 -> 슈퍼비전 -> 로그 분석`

### 7. FT001 사례 소개

현재 7장 유지.

등장인물 설명은 좋다. 발표자가 읽을 때 너무 길게 읽지 않도록 이름과 역할만 남긴다.

### 8. 가족체계 기본 관점

현재 8장 유지.

이 장 뒤에 실제 게임 시연으로 전환한다.

하단 또는 우측에 작은 문구 추가 권장:

`이 순환을 실제 플레이 장면에서 선택지로 다룬다`

### 9. LIVE DEMO 안내 슬라이드 추가

현재 슬라이드에는 실제 시연으로 넘어가는 안내 장이 없다. 8장 뒤에 새 슬라이드 하나를 넣는 것이 좋다.

제목:

`FT001 실제 시연`

본문:

- 가족 구성원의 첫 대화 확인
- 개입 선택지 확인
- 선택 이후 가족 반응 변화 확인
- 선택 로그/슈퍼비전으로 연결

발표자는 이 장을 10초만 보여주고 게임으로 전환한다.

### 10. 개입 선택 = 상담 판단 데이터

현재 9장 유지.

시연 뒤에 돌아와서 "방금 고른 선택이 데이터로 이렇게 남는다"로 연결한다.

### 11. 같은 장면, 다른 다음 대화

현재 10장 유지.

가능하면 이 장에는 좋은 선택/위험 선택 캡처를 조금 더 크게 넣는다. 현재는 좌우 비교가 좋아서 유지 가능.

### 12. 김혜성 슈퍼바이저

현재 11장 유지.

중요 문구:

`정답/오답 채점이 아닌 판단의 복기`

이 문구는 발표에서 꼭 말한다.

### 13. 판단 로그 + 대시보드

현재 12장과 13장은 발표 시간상 합치는 것을 권장한다.

새 제목:

`선택은 로그가 되고, 로그는 분석이 된다`

내용:

- `case_id`, `choice_id`, `theory_lens`, `trust/safety/insight`
- 어떤 선택이 신뢰와 안전감을 높였는가
- 어떤 선택이 아이를 IP로 고정했는가
- 에이전트 유형별 선택 경로 비교

시각 자료:

왼쪽 로그 스키마, 오른쪽 대시보드 캡처.

### 14. FT001 현재 상태

현재 14장 유지하되 표현 수정 필요.

현재 실제 파일 상태:

- 기존 line-by-line CG: 50장
- 새 regen CG 폴더: 현재 확인 기준 15장
- 코드 기준 필요한 최종 CG 슬롯: 67장

따라서 다음 표현으로 바꾼다.

기존:

`새 67장 CG 재생성 중 · 검수 스크립트 준비 완료`

권장:

`코드 기준 67장 CG 슬롯 확인 · 새 CG 세트 재생성/검수 진행 중`

기존:

`통과 후 Unity 적용 · 실행 캡처 갱신 예정`

권장:

`검수 통과분부터 Unity 적용 · 실행 캡처 갱신`

이 장에서 "아직 못했다"보다 "완성 단위를 깊게 만들고 있다"가 먼저 보여야 한다.

### 15. 최종 산출물

현재 15장 유지.

발표 마무리 장으로 사용한다.

마지막 문장:

`가족치료 이론을 설명하는 자료가 아니라, 판단을 직접 플레이하고 복기하는 시스템`

이 문장은 좋으므로 유지한다.

## 부록 처리

### 16. 예상 질문과 답변

발표 중 직접 설명하지 않는다.

별도 Q&A sheet 제출에도 같은 내용을 더 자세히 넣는다.

### 17. 기술 검수 현황

부록으로 유지.

단, CG 관련 표현은 14장과 동일하게 수정한다.

### 18. 최종 제출 자료 구조

부록으로 유지.

### 19. 전환 과정

내용은 좋지만 본편 2-4장과 중복된다. 부록으로 유지한다.

질문을 받았을 때 "왜 방향을 바꿨냐"에 대한 백업 슬라이드로 쓴다.

---

## 게임 시연 위치

권장 위치:

8장 `문제아 찾기가 아니라 반복되는 순환 보기` 설명 후 바로 시연.

이유:

- 가족체계 관점 설명 직후 실제 장면을 보면 이해가 쉽다.
- 9장 선택 데이터 설명으로 자연스럽게 돌아올 수 있다.
- 발표 흐름이 "이론 설명 -> 실제 플레이 -> 데이터화"로 이어진다.

## 게임 시연에서 보여줄 장면

### 필수

1. FT001 사례 진입
2. 어머니 또는 자녀의 첫 발화
3. 개입 선택지
4. 좋은 선택을 골랐을 때 가족 반응 변화

### 가능하면 추가

5. 위험한 선택을 골랐을 때 반응이 달라지는 캡처 또는 짧은 비교
6. 슈퍼바이저 피드백 화면
7. 로그/대시보드 화면

### 시간이 부족하면

게임은 2분 안에 끝내고, 슬라이드 10의 좋은 선택/위험 선택 비교 캡처로 보완한다.

---

## 발표 자료에서 줄여야 할 표현

- `새 67장 CG 재생성 중`을 너무 크게 강조하지 않는다.
- `상용급`, `완성본`, `대규모` 같은 표현은 발표에서 피한다.
- 이미지 제작 진행 상황은 핵심이 아니다.
- 핵심은 학습자, 개입 판단, 가족 반응, 슈퍼비전, 로그 분석이다.

## 슬라이드에 추가하면 좋은 한 장

제목:

`플레이 루프`

구성:

`가족 대화 관찰`
`개입 선택`
`가족 반응 변화`
`슈퍼바이저 피드백`
`선택 로그 저장`
`대시보드/에이전트 분석`

이 장은 현재 6장과 12-13장 사이 내용을 연결해 준다. 다만 총 장수가 늘어나므로, 12장과 13장을 합치는 전제에서 넣는다.
