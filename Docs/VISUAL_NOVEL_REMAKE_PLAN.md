# 가족치료 수련센터 상용 비주얼노벨 전환 계획

- 작성일: 2026-06-08
- 대상 프로젝트: `99_FamilyTherapyPracticumUnity`
- 목표: 수업 과제형 프로토타입이 아니라, 10~15달러급으로 납득 가능한 상용 가족치료 비주얼노벨/상담 시뮬레이션
- 기준 톤: Coffee Talk식 캐릭터 대화 구조 + 상담 수련 시뮬레이션 + 빅데이터 분석 export

## 1. 목표 재정의

이 프로젝트의 목표는 단순히 `FT-001` 한 사례를 데모처럼 꾸미는 것이 아니다. 최종 목표는 가족치료를 배우는 학생이 가상의 상담센터 수련생이 되어, 다양한 가족 사례를 만나고, 캐릭터의 증상과 가족역동을 듣고, 이론 렌즈와 치료 개입을 선택하는 상용급 비주얼노벨 게임이다.

현재 빌드는 기능 프로토타입이다. 사례, 이론, 점수, 슈퍼비전, export는 작동하지만 화면이 카드형 UI와 텍스트 패널 중심이라 실제 상용 게임처럼 보이지 않는다. 상용화를 위해서는 다음 요소가 필요하다.

- 캐릭터 중심 화면
- 상담실/센터 배경
- 표정 변화
- 하단 대화창
- 화자 이름표
- 상담 개입 선택지
- 선택에 따른 반응 대사
- 슈퍼바이저 컷인
- 챕터 진행과 평가서
- 반복 플레이 가능한 사례/로그/분석 구조

## 2. 참고 방향

### 핵심 참고작

- `Coffee Talk`
  - 손님이 찾아와 자신의 문제를 말하고, 플레이어가 대화와 행동으로 반응하는 구조.
  - 이 프로젝트에서는 커피 제조 대신 가족치료 질문, 반영, 구조화, 과제 제안이 플레이어 행동이 된다.
- `VA-11 Hall-A`
  - 손님의 이야기를 듣고 서비스 선택을 통해 서사가 열리는 구조.
  - 상담센터 수련생이 가족의 이야기를 듣고 개입을 선택하는 방식으로 변환한다.
- `Syntherapy`
  - 치료 선택과 관계/결과 분기를 참고한다.
- `Ace Attorney`
  - 증언, 단서, 모순 탐색 구조를 가족역동 단서 찾기에 일부 활용한다.

### 적용 원칙

- 참고작의 플레이 구조와 화면 문법만 참고한다.
- 캐릭터, 배경, 대사, UI는 모두 원본 제작한다.
- 실제 상담을 대체하지 않는 교육용 시뮬레이션이라는 윤리 고지를 유지한다.
- 가족치료 수업 내용과 빅데이터 분석 과목 연결을 게임 시스템 안에 남긴다.

## 3. 상용판 콘텐츠 규모

### 목표 규모

상용화된 프로그램급 목표는 최소 400~500장 수준이 아니라, 실제로 풍부하게 보이려면 600~900장급 자산을 목표로 잡는다.

권장 목표:

```text
상용 최소선: 400~500장
10~15달러급 권장선: 600~900장
풍부한 완성판: 1,000장 이상
```

이 프로젝트의 1차 상용 목표는 다음으로 잡는다.

```text
총 목표 이미지 수: 약 750장
```

### 이미지 자산 상세 산정

| 구분 | 목표 수량 | 설명 |
| --- | ---: | --- |
| 가족 캐릭터/표정 스프라이트 | 약 500장 | 핵심 사례 24개 중심, 가족 구성원별 표정 variation |
| 슈퍼바이저 스프라이트 | 약 60장 | 9명 × 6~7표정 |
| 배경 | 약 40장 | 상담실, 로비, 슈퍼비전실, 자료실, 학교, 가정 방문, 대기실 등 |
| UI/카드/아이콘 | 약 100장 | 대화창, 이름표, 선택지, 사례 파일, 관계도, 이론 카드, 리포트 |
| 이벤트 CG/챕터 컷신 | 약 50장 | 핵심 상담 장면, 챕터 종료, 엔딩/평가서 |
| 합계 | 약 750장 | 10~15달러급 상용판 목표 |

## 4. 사례 구성 목표

현재 데이터셋은 60개 사례를 갖고 있다. 상용판에서는 모든 사례를 같은 밀도로 만들지 않고, 핵심 사례와 실습 사례를 분리한다.

### 핵심 사례

- 총 24개
- 각 사례는 완성형 비주얼노벨 에피소드로 제작
- 사례당 주요 가족 구성원 3~5명
- 사례당 회기 1~2개
- 사례당 대사 라인 80~150개
- 사례당 선택지 12~25개
- 사례당 적절한 개입/부적절한 개입 반응 대사 포함
- 사례당 캐릭터 표정 12~25장

### 실습 사례

- 총 36개
- 짧은 훈련형 사례
- 배경과 일부 공용 캐릭터/실루엣 활용
- 사례당 대사 라인 25~60개
- 사례당 선택지 6~12개
- export와 점수 시스템은 핵심 사례와 동일하게 유지

## 5. 캐릭터 자산 계획

### 가족 캐릭터

상용판에서는 가족 구성원이 실제로 화면에 등장해야 한다. 한 사례 안에서 캐릭터가 증상을 말하고, 플레이어가 치료 개입을 선택하면 표정과 반응이 바뀌어야 한다.

기본 표정 세트:

- 기본
- 불안
- 분노/비난
- 회피/침묵
- 방어
- 슬픔
- 혼란
- 완화/안도

필요 시 사례별 특수 표정:

- 수치심
- 죄책감
- 피로
- 무기력
- 긴장된 웃음
- 눈물
- 경계
- 놀람

### 슈퍼바이저 9명

각 이론 렌즈별 슈퍼바이저는 단순 텍스트가 아니라 캐릭터로 등장한다.

| 이론 | 슈퍼바이저 | 필요 표정 |
| --- | --- | --- |
| 가족체계 기본 | 김혜성 | 기본, 설명, 경고, 승인, 질문, 침묵 |
| Bowen 다세대 | 안우진 | 기본, 분석, 질문, 경고, 승인, 회고 |
| 전략적 가족치료 | 김윤하 | 기본, 날카로움, 역설, 승인, 경고, 미소 |
| 구조적 가족치료 | 이정후 | 기본, 구조화, 단호함, 승인, 경고, 설명 |
| 경험적/Satir | 김연주 | 기본, 공감, 감정확인, 승인, 우려, 따뜻함 |
| 정신역동 가족치료 | 송성문 | 기본, 해석, 침묵, 질문, 경고, 회고 |
| 인지행동 가족치료 | 정세영 | 기본, 교육, 분석, 승인, 과제제시, 경고 |
| 해결중심 가족치료 | 송지후 | 기본, 격려, 질문, 승인, 예외탐색, 미소 |
| 이야기치료 | 박병호 | 기본, 외재화, 질문, 재저작, 승인, 사색 |

파일명은 이름이 아니라 이론 ID 기준으로 유지한다. 예를 들어 김혜성은 `supervisor_system_front.png`, 안우진은 `supervisor_bowen_front.png`에 연결한다. 캐릭터 이름을 나중에 바꿔도 이미지 파일과 코드 참조가 깨지지 않게 하기 위한 정책이다. 성별은 현재 생성된 이미지 방향을 유지한다.

## 7. UI/UX 전환 계획

### 기존 화면의 문제

- 카드와 텍스트가 많아 업무용 툴처럼 보인다.
- 캐릭터가 없어 감정과 서사가 약하다.
- 선택지가 학습 문제처럼 보인다.
- 상담실 현장감이 부족하다.

### 상용판 화면 구조

1. 메인 메뉴
   - 상담센터 외관 또는 로비 배경
   - 주요 슈퍼바이저 캐릭터 배치
   - 캠페인 시작, 이어하기, 사례 데이터, 설정

2. 상담센터 로비
   - 오늘 접수된 사례 카드
   - 슈퍼바이저 일정
   - 수련생 평가 상태

3. 사례 파일 화면
   - 종이 파일 UI
   - 가족 관계도 아이콘
   - 주요 등장인물 얼굴 썸네일

4. 회기 비주얼노벨 화면
   - 상담실 배경
   - 가족 캐릭터 2~4명 배치
   - 하단 대화창
   - 화자 이름표
   - 현재 화자 강조
   - 상담자 선택지

5. 개입 선택 화면
   - 질문 카드
   - 반영 카드
   - 구조화 카드
   - 과제 카드
   - 윤리/안전 카드

6. 슈퍼비전 화면
   - 슈퍼바이저 캐릭터 컷인
   - 점수/해설
   - 놓친 가족역동
   - 다음 수련 목표

7. 데이터 대시보드
   - 기존 export 기능 유지
   - 시각적으로는 게임 내 수련 평가 리포트처럼 표현

## 8. 게임 시스템 전환

### 기본 루프

```text
센터 로비
-> 사례 선택
-> 사례 파일 확인
-> 회기 입장
-> 가족 대화 청취
-> 치료 개입 선택
-> 가족 반응 확인
-> 슈퍼바이저 피드백
-> 플레이 로그/분석
-> 다음 사례
```

### 선택지 유형

- 합류 질문
- 순환질문
- 감정 반영
- 구조화
- 경계 만들기
- I-position
- 행동계약
- 외재화 질문
- 예외질문
- 안전 계획
- 성급한 진단
- IP 고정
- 회피적 서류 확인
- 상담자 중심 결론 통보

### 점수 축

기존 점수 축을 유지하되 화면에서 더 게임적으로 보여준다.

- 치료 동맹
- 안전감
- 가족역동 통찰
- 이론 적합도
- 실행 가능성

## 11. 검증 계획

### 기능 검증

- Windows 빌드 성공
- 런타임 스모크 성공
- `visualNovelMode=true`
- `vnCharacterCount>=100` 목표 단계별 확인
- `vnBackgroundCount>=20` 목표 단계별 확인
- 모든 핵심 사례가 VN script를 갖는지 확인
- export CSV/JSON 생성 확인

### 화면 검증

- 1600x900 기준 캐릭터와 대화창이 겹치지 않는지 확인
- 1280x720에서도 텍스트가 잘리지 않는지 확인
- 현재 화자가 명확히 보이는지 확인
- 선택지 카드가 4개까지 안정적으로 표시되는지 확인
- 슈퍼바이저 컷인이 대화창을 가리지 않는지 확인

### 콘텐츠 검증

- 각 사례가 실제 가족치료 이론과 연결되는지 확인
- 부적절한 선택지가 단순 오답이 아니라 왜 문제인지 해설되는지 확인
- 실제 상담 조언처럼 오해될 문구가 없는지 확인
- 합성 사례/비대체 고지가 유지되는지 확인

## 15. 결론

상용화된 프로그램급을 목표로 한다면 필요한 이미지는 수십 장이 아니라 수백 장 단위다. 이 프로젝트의 현실적인 상용 목표는 약 750장 규모의 이미지 자산과 24개 핵심 비주얼노벨 사례다.
