## 2. 전체 결론

현재 디자인은 이전의 조잡한 장식 UI보다 방향이 훨씬 명확해졌다. `Eliza`식 clinical VN UI를 기준으로 잡은 결정은 맞다.

하지만 현재 실행 화면은 아직 상업 출시 수준이 아니다. 목업은 가능성을 보여주지만, Unity 화면은 여전히 교육용 프로토타입 또는 내부 학습 앱에 가깝다.

가장 큰 문제는 세 가지다.

1. 실제 빌드가 목업 품질을 따라오지 못한다.
2. 한글 텍스트가 작고 밀도가 높아 읽는 피로가 크다.
3. 상담 선택이 아직 “상담 장면을 플레이한다”보다 “정답/오답을 고른다”에 가깝다.

현재 상태를 한 문장으로 정리하면:

> 좋은 방향의 목업은 생겼지만, 실제 게임 화면은 아직 상업 VN이 아니라 방향성 검증용 빌드다.

## 3. Sub Agent별 평가

### A. 상업 VN 아트디렉터 관점

성격: 냉정한 상업 출시 기준, 첫인상과 아트 완성도 중심.

판정:

- 현재는 상업 비주얼노벨보다 교육용 Unity 프로토타입에 가깝다.
- 목업은 시장성 있는 기준을 어느 정도 보여주지만, 실제 빌드가 그 수준을 따라오지 못한다.

주요 지적:

- 치명: 실제 빌드와 목업 사이의 품질 차이가 크다.
- 치명: 팔리는 게임의 첫인상, 즉 캐릭터·장면·감정·긴장감이 약하다.
- 높음: 배경, UI, 문서 패널, 캐릭터가 서로 다른 제품에서 온 것처럼 보인다.
- 높음: 캐릭터가 상담실 안에 존재한다기보다 PNG가 배경 위에 얹힌 느낌이다.
- 높음: UI 아트가 아직 기본 박스 수준이다.
- 중간: 전체 무드가 너무 무겁고 단조롭다.
- 중간: `Eliza` 영향은 있으나 한국 가족치료 수련만의 고유 브랜드가 약하다.
- 중간: 한국어 타이포그래피 계층이 부족하다.

추천:

- 목업을 참고 이미지가 아니라 최종 UI 컴포넌트 사양으로 쪼갠다.
- top HUD, case panel, choice row, report panel을 각각 9-slice/프리팹 기준으로 재제작한다.
- 캐릭터별 조명 방향, 발 위치, 스케일, 그림자, 배경 블러 규칙을 통일한다.
- 대시보드는 내부 분석 툴이 아니라 수련 기록실/슈퍼비전 회고 화면으로 재연출한다.

### B. UX / 한국어 가독성 리뷰어 관점

성격: 작은 해상도, 한글 가독성, 상호작용 명확성 중심.

판정:

- 1024x768에서 `textOverflowCount=0`, `offscreenRectCount=0`이므로 화면은 깨지지 않는다.
- 하지만 “깨지지 않는다”와 “읽기 좋다”는 다르다.
- 현재 핵심 문제는 작은 글자와 정보 밀도다.

주요 지적:

- 심각도 상: 한글 텍스트가 너무 작고 빽빽하다.
  - `04_ft001_intake`: 텍스트 28개 중 tiny text 26개.
  - `07_ft001_choice_deck`: 텍스트 9개 중 tiny text 8개.
  - `01_main_menu`: 텍스트 14개 중 tiny text 10개.
- 심각도 상: 선택지 버튼 affordance가 약하다.
  - 선택지가 클릭 가능한 상담자 개입인지, 단순 정보 행인지 즉시 구분이 약하다.
- 심각도 상: 사례 파일 화면의 우선순위가 불명확하다.
  - 사례 요약, 슈퍼바이저 브리핑, 이론 렌즈, 회기 입장이 동시에 비슷한 무게로 보인다.
- 심각도 중: 메인 메뉴 버튼 위계가 약하다.
- 심각도 중: 반투명 패널과 배경이 본문 가독성을 방해한다.
- 심각도 중: 한국어 문장 길이와 전문용어 밀도가 높다.

추천:

- 1024x768 기준 본문 최소 16px급, 보조 라벨 최소 13-14px급으로 잡는다.
- 사례 설명은 긴 문단 대신 2-4줄 단위 섹션으로 나눈다.
- 선택지는 제목 1줄 + 보조 설명 1줄 구조로 바꾼다.
- `회기 입장`, `새 게임/이어하기` 같은 1차 행동을 명확하게 분리한다.
- AI 슈퍼바이저는 버튼보다 토글로 표현한다.

### C. 가족치료 교육 / Serious Game 관점

성격: 가족치료 학습 목표, 체계적 사고, 슈퍼비전 경험 중심.

판정:

- 현재 설계는 가족체계 개념을 “말로 설명”하는 데는 성공한다.
- 그러나 플레이어가 회기 안에서 체계적으로 사고하고 시행착오로 배우는 게임 경험은 아직 약하다.

주요 지적:

- 높음: 선택지가 시험형으로 읽힌다.
  - 실제 상담자 발화보다 정답/오답 고르기에 가깝다.
  - 나쁜 선택지가 너무 명백히 나빠 학습적 딜레마가 약하다.
- 높음: IP 비난 회피가 사후 설명에 의존한다.
  - 회기 중 가족 반응, 표정, 침묵, 방어 상승으로 체험하게 하는 장치가 부족하다.
- 중간: 사례 파일의 체계 단서는 좋지만 조작감이 약하다.
  - 플레이어가 관계도나 순환도를 직접 표시하거나 가설화하지 않는다.
- 중간: 슈퍼비전은 유용하지만 끝난 뒤 채점자처럼 보인다.
  - 회기 중 사고를 돕는 내면 조언자 느낌이 약하다.
- 중간: `Eliza` 목업 방향은 교육 목표와 잘 맞지만 실제 화면은 아직 학습 앱 인상이 남는다.

추천:

- 모든 선택지를 실제 상담자 발화문으로 재작성한다.
- 오답도 초보 상담자가 실제로 할 법한 그럴듯한 개입으로 만든다.
- IP화 선택 시 가족 대사가 즉시 방어적으로 변하고, 신뢰/안전 변화가 표정과 침묵으로 먼저 드러나야 한다.
- 사례 파일에서 `IP`, `순환`, `경계`, `삼각관계`를 직접 태깅하는 활동을 추가한다.
- 슈퍼비전을 사후 점수표뿐 아니라 선택 직전 코멘트, 회기 중 중단 질문, 선택 후 반성 질문으로 확장한다.

## 4. 세 리뷰의 공통 합의

세 리뷰어가 모두 동의한 점:

1. `Eliza` 기준으로 방향을 바꾼 것은 맞다.
2. 목업은 현재 실행 화면보다 훨씬 좋은 방향이다.
3. 실제 Unity 화면은 아직 목업 품질을 따라오지 못한다.
4. 현재는 상업 출시 화면이 아니라 방향성 검증용 빌드다.
5. 선택지 화면은 가장 먼저 고쳐야 하는 핵심 화면이다.
6. 사례 파일 화면은 정보량과 위계를 다시 설계해야 한다.
7. 슈퍼비전 리포트는 점수표가 아니라 회고/학습 장면으로 재연출해야 한다.
8. 캐릭터와 배경 합성이 아직 상업 VN 수준이 아니다.

## 5. 다음 작업 우선순위

### 1순위: Unity 화면을 목업 04/06/07/09 수준으로 끌어올리기

대상:

- 사례 파일
- 회기 대화
- 개입 선택
- 슈퍼비전 리포트

해야 할 일:

- 목업을 UI 컴포넌트 사양으로 분해한다.
- 패널, HUD, 선택지 row, 리포트 panel을 프리팹/헬퍼 단위로 재정의한다.
- 큰 네모 패널과 단순 버튼을 제거한다.

### 2순위: 선택지의 게임성 재작성

해야 할 일:

- 선택지는 이론명/정답 선택이 아니라 실제 상담자 발화로 쓴다.
- 모든 선택지는 그럴듯해야 한다.
- 틀린 선택도 “초보 상담자가 실제로 할 법한 실수”여야 한다.
- 선택 후 가족 표정, 대사, 침묵, 방어 상승으로 결과를 보여준다.

### 3순위: 한글 가독성 재설계

해야 할 일:

- 1024x768 기준 본문 최소 크기 정책을 세운다.
- 긴 문단을 정보 블록으로 나눈다.
- 제목, 본문, 보조 정보, 버튼 라벨의 폰트 계층을 분리한다.
- tiny text를 줄이는 것을 단순 감사 수치가 아니라 품질 기준으로 둔다.

### 4순위: 캐릭터/배경 합성 규칙 통일

해야 할 일:

- 캐릭터 스케일, 발 위치, 조명 방향, 그림자, 선명도를 통일한다.
- 비활성 캐릭터는 단순 투명도가 아니라 명도/채도/초점으로 구분한다.
- 배경 시간대와 상담 긴장도에 따른 색온도 변주를 만든다.

### 5순위: 가족치료 조작감 추가

해야 할 일:

- 사례 파일에서 IP, 순환, 경계, 삼각관계 태깅을 추가한다.
- 선택 결과가 플레이어의 가설과 연결되게 만든다.
- 슈퍼바이저는 사후 채점자뿐 아니라 회기 중 사고를 돕는 조언자로 배치한다.

## 7. 최종 판단

현재 디자인은 “망했다”기보다 “이제야 제대로 된 기준을 잡은 초기 단계”에 가깝다.

`Eliza`식 목업은 좋은 방향이다. 하지만 목업을 문서에만 두면 의미가 없다. 실제 Unity 화면이 여전히 큰 패널, 작은 글자, 기본 버튼, 점수표 중심이면 사용자는 상업 VN이 아니라 수업용 앱으로 느낄 것이다.

다음 작업은 새 이미지를 더 만드는 것이 아니라, 이미 생성된 `03`, `04`, `06`, `07`, `09` 목업을 기준으로 실제 UI 컴포넌트를 재제작하는 것이다. 특히 `07_intervention_choice`의 얇은 선택 리스트와 `09_supervision_report`의 리포트 구조를 실제 빌드에 먼저 옮겨야 한다.

가장 중요한 결론:

> 현재 목업 방향은 맞다. 현재 실행 화면은 아직 아니다.
